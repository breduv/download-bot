# DW Bot

Telegram-бот для поиска и скачивания аудио, видео и фотогалерей по ссылке или названию трека.

Бот использует Spotify для поиска и получения метаданных, `yt-dlp` для аудио и видео, а `gallery-dl` — для фотогалерей TikTok. Загруженные файлы сохраняются во временный каталог и удаляются после отправки пользователю.

## Возможности

| Источник | Что делает бот |
| --- | --- |
| Текстовый запрос | Ищет треки в Spotify и предлагает выбрать результат |
| Spotify | Получает метаданные трека, скачивает аудио, добавляет название, исполнителя и обложку |
| YouTube | Показывает доступные разрешения видео и вариант «Только звук» |
| YouTube Shorts | Скачивает видео напрямую |
| YouTube Music | Скачивает аудио |
| TikTok | Скачивает видео, раскрывает короткие ссылки и отправляет фотогалереи |
| Instagram | Скачивает видео по публичной ссылке |
| Pinterest | Скачивает видео по публичной ссылке |
| VK / VK Видео | Скачивает клипы |

Фотографии TikTok отправляются медиагруппами до 10 файлов. Если в последней группе остаётся одна фотография, она отправляется отдельным сообщением.

## Требования

- Python 3.11 или новее (Docker-образ использует Python 3.12);
- FFmpeg и `ffprobe` в `PATH`;
- Deno в `PATH` для JavaScript-компонентов `yt-dlp`;
- токен Telegram-бота;
- Spotify Client ID и Client Secret;
- доступ к поддерживаемым сайтам напрямую или через прокси.

Docker-образ уже содержит Python, FFmpeg и Deno.

## Настройка окружения

Создайте файл `.env` в корне проекта:

```dotenv
BOT_TOKEN=telegram-bot-token
SPOTIFY_CLIENT_ID=spotify-client-id
SPOTIFY_CLIENT_SECRET=spotify-client-secret

# Необязательно
MEDIA_PROXY=
TELEGRAM_PROXY=
LOG_LEVEL=INFO
SEARCH_LIMIT=5
MAX_UPLOAD_SIZE_MB=49
```

| Переменная | Обязательна | Значение |
| --- | --- | --- |
| `BOT_TOKEN` | Да | Токен Telegram-бота |
| `SPOTIFY_CLIENT_ID` | Да | Client ID приложения Spotify |
| `SPOTIFY_CLIENT_SECRET` | Да | Client Secret приложения Spotify |
| `MEDIA_PROXY` | Нет | Прокси для Spotify, `yt-dlp` и `gallery-dl` |
| `TELEGRAM_PROXY` | Нет | Прокси для подключения к Telegram Bot API |
| `LOG_LEVEL` | Нет | `DEBUG`, `INFO`, `WARNING`, `ERROR` или `CRITICAL`; по умолчанию `INFO` |
| `SEARCH_LIMIT` | Нет | Количество результатов поиска Spotify, от 1 до 10; по умолчанию 5 |
| `MAX_UPLOAD_SIZE_MB` | Нет | Максимальный размер одного медиафайла; по умолчанию 49 МБ |

Файл `.env` находится в `.gitignore`. Не добавляйте токены и секреты в репозиторий.

## Локальный запуск

PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
python main.py
```

Перед запуском убедитесь, что команды `ffmpeg`, `ffprobe` и `deno` доступны из терминала.

## Запуск через Docker Compose

```powershell
docker compose up -d --build
```

Просмотр логов:

```powershell
docker compose logs -f download-bot
```

Остановка:

```powershell
docker compose down
```

Образ можно пометить собственным тегом через переменную `IMAGE_TAG`:

```powershell
$env:IMAGE_TAG = "dev"
docker compose up -d --build
```

## Как это работает

1. `SearchService` определяет тип запроса и источник ссылки.
2. Для результатов Spotify и форматов YouTube бот показывает inline-клавиатуру.
3. `DownloadService` направляет запрос подходящему провайдеру.
4. Провайдер скачивает и проверяет файл, при необходимости добавляет метаданные и обложку.
5. `BotHandlers` отправляет результат пользователю и очищает временный каталог.

Основные компоненты:

```text
app/
├── bot/          # Telegram-обработчики, роутер и клавиатуры
├── core/         # Настройки и конфигурация логирования
├── errors/       # Внутренние исключения и публичные сообщения
├── models/       # Модели поисковых запросов и медиа
├── providers/    # Spotify, yt-dlp, gallery-dl и работа с обложками
└── services/     # Разбор запросов и координация скачивания
```

Точка входа — `main.py`. Зависимости проекта зафиксированы в `requirements.txt`.

После обновления зависимостей рекомендуется проверить импорт и синтаксис:

```powershell
python -m compileall -q app
```

## Логирование и ошибки

Логи выводятся в stdout и содержат время, модуль, строку и уровень события. Для обработанных ошибок записываются внутренний код, компонент, операция и технические детали. Пользователю отправляется отдельное безопасное сообщение без traceback и внутренних данных.

Для диагностики установите:

```dotenv
LOG_LEVEL=DEBUG
```

## Ограничения

- Работа зависит от Spotify, Telegram и структуры поддерживаемых сайтов.
- После изменений на стороне YouTube, TikTok и других платформ может потребоваться обновление `yt-dlp` или `gallery-dl`.
- Приватный, удалённый, возрастной или регионально ограниченный контент может быть недоступен.
- Каждый файл проверяется по `MAX_UPLOAD_SIZE_MB`; лимиты Telegram могут дополнительно зависеть от типа медиа.
- Бот предназначен для материалов, которые пользователь имеет право скачивать и распространять.

## CI/CD

`.gitlab-ci.yml` собирает Docker-образ для ветки `main`, передаёт тег через dotenv-артефакт и разворачивает сервис командой `docker compose up`. Runner должен иметь доступ к Docker и каталогу развёртывания.
